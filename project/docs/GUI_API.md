# Согласование AR с веб-интерфейсом

Документ для разработчика сайта на HTML/CSS/JavaScript. Это проект контракта: HTTP-сервер и выбор пользовательского полигона пока не подключены к рабочему циклу AR.

## Что делает AR

AR измеряет поверхность, считает высоту над откалиброванной плоскостью пола и отправляет цветное изображение на проектор. Пол — 0 м, рабочий диапазон — 0–0,50 м. Измеренные поверхности выше 0,50 м получают чёрный цвет. Они продолжают перекрывать свет на более дальние поверхности в 3D-модели проектора. Заполнение пропусков не должно закрашивать намеренно исключённые объекты.

При неподвижной сцене изображение удерживается. Во время изменений ориентир — одно обновление в секунду; фактический интервал зависит от расчёта. Изменение настроек в GUI должно заново отобразить последний снимок даже при неподвижной сцене.

GUI отвечает за кнопки, предпросмотр и рисование рабочей зоны. Вычисления глубины и формирование проекции выполняет AR. Управление техникой остаётся отдельной частью проекта.

## Поле проектора и выбранная зона

Калибровка связывает камеры со всем доступным полем проектора. Поверх неё применяется пользовательская маска. Выбор меньшей зоны сохраняет её физическое положение: изображение за пределами полигона становится чёрным. Преобразование камеры в проектор при этом сохраняется.

Рекомендуемый интерфейс: предпросмотр выходного изображения проектора, на котором пользователь задаёт прямоугольник или простой полигон мышью. Сайт может показывать поля, углы и подсказки поверх предпросмотра; сами элементы управления не попадают в физическую проекцию.

Координаты полигона нормализованы относительно полного изображения проектора: начало сверху слева, X вправо, Y вниз. Для размера W × H: u = x/W, v = y/H; это координаты границ изображения. Все вершины должны находиться в доступном поле. Самопересечения и пустые области отклоняются. Маска может быть вогнутой, от 3 до 32 вершин.

Текущая временная настройка: экран 1280 × 800, доступный прямоугольник `[268, 40, 1012, 760]`, центральное поле примерно 90 × 90 см. Его нормализованные границы: X от 0,209375 до 0,790625, Y от 0,05 до 0,95. Это прежний квадрат около 1 × 1 м с отступами по 5 см со всех сторон. После окончательной настройки эти значения нужно получить от AR, а не зашивать в сайт.

## Предлагаемые HTTP-запросы

Адрес API и место запуска согласуются отдельно. Для разработки предполагается AR на том же компьютере и адрес вида `http://127.0.0.1:8765`. Если сайт работает с другого компьютера, потребуются согласованные сетевой адрес и разрешённый origin.

| Запрос | Результат |
|---|---|
| `GET /api/v1/state` | Готовность калибровок, размеры поля, настройки, номер последнего снимка, частоты и ошибки |
| `GET /api/v1/preview.jpg` | Последнее выходное изображение проектора для рисования зоны в GUI |
| `POST /api/v1/settings` | Атомарное применение диапазона высот, палитры и рабочей маски |
| `POST /api/v1/actions/rescan` | Новое построение поверхности |
| `POST /api/v1/actions/calibrate-floor` | Начало процедуры нулевой плоскости с указанием освободить пол |

Начать достаточно с опроса состояния/предпросмотра 1–2 раза в секунду. При необходимости поток состояний можно позднее добавить через WebSocket. Большие карты высот в JSON на каждый кадр не требуются для этих элементов управления.

Пример настроек:

```json
{
  "schema_version": 1,
  "request_id": "scene-17",
  "projection_revision": "revision-from-state",
  "height_range_m": [0.0, 0.5],
  "above_range": "black",
  "palette_gamma": 0.5,
  "update_interval_s": 1.0,
  "roi": {
    "coordinate_space": "projector_normalized",
    "vertices": [[0.25, 0.15], [0.75, 0.15], [0.75, 0.85], [0.25, 0.85]]
  }
}
```

Успешный ответ содержит `request_id`, принятую `settings_revision` и номер снимка, к которому применены настройки. Некорректные значения возвращают ошибку с именем поля; прежние настройки сохраняются целиком. При смене проектора, разрешения или калибровки меняется `projection_revision`; маска для старой ревизии должна быть повторно согласована с пользователем.

В состоянии нужны стадии `mount_pending`, `stereo_required`, `floor_required`, `projector_required`, `ready`. Отдельно передаются частота проверок, число обновлений, возраст изображения и доля измеренной/восстановленной поверхности. Статус `ready` для точного AR на рельефе требует принятой 3D-калибровки проектора.

## Что согласовать с коллегой

1. Где будут работать сайт и AR: один компьютер или локальная сеть; адрес API и origin сайта.
2. Достаточно ли прямоугольника или сразу нужен произвольный полигон.
3. Как показывать состояния калибровки и запускать её шаги из GUI.
4. Как сохранять несколько рабочих зон и восстанавливать их после перезапуска.

Линии одинаковой высоты, как в видео-примере, добавляются после проверки измерений и попадания проекции. Их шаг можно впоследствии включить в настройки. Текущая реализация цветной карты пока не содержит этих линий.
